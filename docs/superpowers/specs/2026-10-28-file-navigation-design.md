# File navigation — design

Deepen the existing user file-navigation transition; keep the native dialog/overlay owner. Centralize membership validation, overlay closure, Explorer navigation, file selection, phone/tablet pane/focus and desktop overlay-origin focus. Invalid or stale paths make no state/focus changes. Use one transition for sidebar, safe file chips, palette pointer and keyboard, canvas clicks, hotspot and cycles. Internal agent focus remains separate and keeps Ask visible.

Eliminate duplicate capture/bubble and palette direct/delegated routes. Keep global `selectFileFromUi(path, panToNode=true)` signature. Move it beside shell/overlay logic if useful; file rows use the existing delegated listener, actions retain direct handling, palette Enter calls the same transition. Phone selects Impact and focuses inspector, tablet closes sheet and focuses canvas; desktop inline clicks keep a surviving visible control focused, restore its equivalent after redraw when available, otherwise focus Map; overlay-origin navigation focuses Map. Canvas click keeps panToNode=false and any drag exceeding the movement threshold must not act as click even if released near its start. Never use blanket propagation suppression.

Preserve native showModal/close, original launcher on overlay transfers, Escape/backdrop/close restoration, exactly one dialog, live DOM region identity, file-list scroll, resize behavior, graph/layout/state, script ordering, accessible names and grounded safe paths with quotes/angle/ampersand/Unicode. No intake, repository replacement or agent logic behavior changes.

Tests exercise production registered handlers: palette click/Enter once, stale path/result inert, sidebar/sheet/phone/tablet/desktop focus, agent internal focus, canvas click/drag, overlay transfers and resize, special paths, Evals/Docs/Ask chips. Native dialog focus and asynchronous close events require real browser checks; reuse unchanged existing lifecycle evidence. User authorized recommended defaults and one-by-one execution.
