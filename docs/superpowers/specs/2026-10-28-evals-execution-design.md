# Shared Evals execution — design

Move complete benchmark orchestration from the browser into the existing DOM-free CartographEvals module so browser and Node tests exercise the same actual run. Preserve the existing strict/naive scoring, graph-derived benchmark cases, actual tool trace, summary weighting/rounding and full result shape. Keep existing four shared exports and add evaluateSuite(graph, mode, chipFormatter) returning {isStrict,cases,entries,summary}. Mode is strict or naive; invalid mode fails before planning/scoring. Formatter is the existing planner HTML-string seam, supplied safely by browser; numeric scoring uses citations/trace, never parsed HTML. No new dependency, script, framework, network or provider abstraction.

Strict executes the current planner once per case, uses actual trace/provenance and aggregates actual step count; naive never invokes planner and uses existing existence-only scoring/fake paths. Empty graph returns zero cases and existing empty aggregate semantics to Node callers; browser Run keeps evalRun null/Not run on empty graph. Do not force naive failure where fake paths coincide with actual graph files. Repeated runs are deterministic and do not mutate the graph.

Browser Run remains sole execution trigger. Render, opening Evals and view switching never run the suite; real mode changes or repository replacement clear previous results; selecting the already-active mode preserves results. Strict trace and answer use existing safe chip formatter; naive uses existing escaped grounded text. No conversation, selection, highlights, fetch or model endpoint action as a side effect. Preserve UI, snapshot, parser, agent, navigation and graph behavior.

Tests at shared suite seam cover strict/naive/empty/invalid mode/determinism, weighted totals, trace and formatter; retain genuine primitive scoring tests. Production browser tests cover no implicit execution, explicit Run, mode and graph replacement invalidation, snapshot graphs and safe special-character paths, with actual expanded trace/answer. User authorized recommended defaults and one-by-one execution.
