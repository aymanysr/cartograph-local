# Repository intake — agreed design

Cartograph should map the same available repository files whether opened in the browser or scanned by the CLI. Both paths retain their existing platform-specific readers; a small shared, deterministic, DOM-free intake policy decides inclusion. Snapshot inputs keep their recorded files and are not filtered again. Presets and manual-file insertion remain unchanged.

The user approved these fixed defaults: supported extensions `.ts .tsx .js .jsx .mjs .cjs .py .go .css .json` (case-insensitive); skip hidden files and path segments and the existing CLI dependency/build directories (`node_modules`, `dist`, `build`, `out`, `coverage`, `__pycache__`, `venv`, `vendor`, `target`; hidden dirs already skipped); reject files over 500,000 bytes, not characters. The selected root itself is not filtered. Treat excluded directory names as whole path segments. Normalize path separators. Do not follow CLI symlinks.

Report skipped entries with concise per-reason counts and accessible details: excluded/hidden directories, unsupported files, oversized files, unreadable files/directories and duplicate paths as applicable. Limit displayed entries to 100 and state when more exist. A pruned directory is one skipped entry, not an invented count of its descendants. When all selected files are skipped, preserve the existing graph and show the attempted scan report. Do not apply the 500k rule or exclusions to graph or files snapshots. Do not alter snapshot/export schemas.

Use actual File.size and Node byte counts, including verifying actual bytes read if a file changes after stat. Report unreadable nested paths while continuing siblings; a bad CLI root remains a clear fatal error. Preserve folder-relative paths; strip a root only for webkitRelativePath with one shared root. Preserve distinct roots for mixed-root inputs; plain file names are not stripped. Report and avoid duplicate graph paths. The browser can only process files the platform supplies.

A shared classic/CommonJS `lib/cartograph-intake.js` houses deterministic path/size classification; the existing parser stays standalone and unchanged. Existing six app scripts and no-build direct-file startup remain; the new shared library loads before the app. The same policy is consumed by the CLI without DOM or network. Browser output uses accessible native details and safe text rendering; CLI prints readable summaries. Existing loaded selection, agent grounding, script bootstrap, Evals, preset and drag/drop behavior remain intact.

Tests cover accepted file parity on actual CLI and browser handler with CSS/CJS/UTF-8 byte boundaries, dot paths, excluded directories and deceptive near-matching names; selected-root handling; unreadable and duplicate files; all-skipped behavior; both snapshot forms; ordinary JSON; accessible reporting; direct-file and server loading. Full Node suite and focused browser verification are required. User authorized recommended defaults without further routine questions.
