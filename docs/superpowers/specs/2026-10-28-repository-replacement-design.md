# Repository replacement — design

Deepen the existing graph replacement module rather than introduce a new abstraction. A repository adoption owns consistent raw files, graph identity, provenance, selection, stale transient state, repository label and one final refresh. Parse input before mutating current state. A parser error through any preset, folder or pasted-file handler preserves the prior graph, raw files, provenance, selection and dropdown; Last intake may still describe the attempted scan. Preserve the established parser, no-build globals, export/snapshot schemas, all intake rules and Last intake report (which describes the last attempt, including an all-skipped attempt).

Behavior: default adoption preserves the selected path if present else selects the existing highest-impact fallback; preset adoption deliberately selects its fallback even if old paths overlap; pasted-file adoption selects the inserted path and pans to it. Empty graphs select none. Resolve selection before final rendering; keep agent/internal selection distinct from user file navigation. Reset draggingNode and panningCanvas in addition to existing hover, simulation/isolation, Evals, agent highlights/conversation/question. Always adopt a fresh graph object so in-flight model responses for a previous graph remain stale. Preserve active view, filters, sort, focus/sheets, pane, scroll and collapse state.

Centralize the existing custom dropdown label decision in adoption for uploaded folders, graph/files snapshots and CLI preload while preserving each label text and success toast. Presets preserve their native option; pasted-file insertion keeps the current label. Do not relocate intake-report ownership or alter snapshot parsing.

Guard delayed startup preload: if a user has replaced the graph since the preload began, do not adopt its delayed success, fall back to the sample, or run the startup demo/selection against that user's graph. Initial application setup, resize listener and animation still initialize. Preserve existing direct-file fallback and ordinary successful preload/demo. Do not add a general concurrency framework or change last-completed behavior for two concurrent folder reads.

Test production lifecycle through real code: same-count graph replacement, empty graph, provenance/raw files/export, preset and pasted-file selection, drag/pan, stale Evals and agent output, preserved UI/intake state, preload success/failure after user replacement, delayed agent success and failure, hidden canvas fit. Focused browser checks cover replacement during drag, modal/focus and delayed startup; reuse unaffected prior UI checks. User authorized recommended defaults and a one-by-one implementation, no new routine questions.
